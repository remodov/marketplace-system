# Замер поиска

Тесты идут на H2 и про скорость ничего не говорят. Числа снимаются на настоящей
базе — на той, что поднимает стенд.

```bash
docker compose -f ../../infra/compose.yaml up -d postgres-catalog redis
../../gradlew :catalog-starter:bootRun
```

Наполнить каталог и снять первое число:

```bash
psql postgresql://catalog:catalog@localhost:5438/catalog -f bench/generate.sql
bench/measure.sh "keychron модель 54321"
```

Посмотреть, что делает база:

```sql
explain analyze select * from products where lower(title) like '%keychron%';
```

`Seq Scan` на ста тысячах строк — это и есть ответ на вопрос, почему стало
медленно. Обычный btree-индекс по `title` здесь не помогает: он умеет искать по
началу строки, а `LIKE '%…%'` начала не знает.

Что снять по ходу шага:

| момент | что замерить |
|---|---|
| до индекса | среднее время ответа и план запроса |
| после индекса | то же самое, на тех же данных |
| повторный запрос карточки | время первого и второго `GET /products/{id}` |

Разница в числах и есть результат шага — не «стало быстрее», а «было 380 мс,
стало 12 мс».
