# Б1. Notification на Kotlin

## Зачем этот шаг

Сервис уведомлений — самый маленький в системе и с самой понятной логикой.
На нём разница между языками видна построчно, без споров о вкусах.

Kotlin здесь уже подключён: плагин в сборке, `kotlin-stdlib` в зависимостях,
исходники в `src/main/kotlin`, тесты в `src/test/kotlin`. Сервис при этом
остаётся смешанным — Java и Kotlin живут в одном модуле, как это и бывает при
постепенном переезде.

## Что нужно сделать

Перенести подстановку `${var}` → значение в `TemplateRenderer.kt`.

Java-версия делала это циклом по `Matcher` с `appendReplacement`. На Kotlin
короче: `Regex.replace` принимает лямбду, а отсутствующее значение закрывается
элвис-оператором `?:`. Пустое поле шаблона — обычный случай, а не ошибка: письмо
должно уйти, а не упасть.

## На что посмотреть по дороге

- `data class` против `record`: что даёт первое сверх второго и чего стоит.
- Nullable-типы: в Java поля шаблона могли быть `null`, и об этом надо было
  помнить. Здесь компилятор не даст забыть — посмотри на `String?` в сигнатуре.
- Взаимодействие с Java: `NotificationService` написан на Java и зовёт этот
  класс. Обрати внимание, как поменялись имена методов у результата (`subject()`
  у record против `getSubject()` у data-класса) — при переезде это первое, что
  ломается.
- Что не стоит делать: переписывать сервис целиком «потому что Kotlin лучше».
  Смешанный модуль — нормальное состояние на годы.
