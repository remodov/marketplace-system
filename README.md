# Маркетплейс: сквозная система для практики

Рабочая система из разбора [«Как разбить систему на сервисы»](https://vikulin-va.ru/case/services-map/):
шесть сервисов с собственными базами, событиями через Kafka и сагой на оформлении
заказа. Её можно поднять, потрогать и читать как образец — и на ней же построен
[практикум из пятнадцати шагов](docs/practicum/PLAN.md).

## Что внутри

| сервис | отвечает за | не делает |
|---|---|---|
| `services/catalog` | карточки, остатки, поиск, модерация | не считает деньги |
| `services/order` | корзина, заказ, резерв, статусы | не пишет в каталог |
| `services/payment` | платежи, эскроу, выплаты | не знает про заказы |
| `services/notification` | email, sms, push по команде | ничего не решает само |
| `services/customer` | identity, профили, авторизация | не хранит товары |
| `services/backoffice` | модерация, споры, аудит | не правит чужие данные напрямую |

Границы взяты из кейса и держатся намеренно: ограничение «что сервис **не** делает»
здесь важнее списка его функций.

## Поднять стенд

```bash
docker compose -f infra/compose.yaml up -d
docker compose -f infra/compose.yaml ps
```

Поднимаются: по своей PostgreSQL на каждый сервис (общей базы у сервисов нет),
Kafka, Redis, MongoDB, Elasticsearch и Keycloak.

| что | порт | зачем |
|---|---|---|
| PostgreSQL catalog / order / customer / notification / backoffice / payment | 5432–5437 | источник правды каждого сервиса |
| Kafka | 9092 | события заказа, outbox, сага |
| Redis | 6379 | кэш карточек, счётчики лимита частоты |
| MongoDB | 27017 | журнал доставок и шаблоны уведомлений |
| Elasticsearch | 9200 | поиск по каталогу |
| Keycloak | 8081 | выдача токенов; сервисы проверяют подпись локально |

## Собрать и прогнать тесты

```bash
./gradlew buildAll     # собрать все сервисы
./gradlew testAll      # прогнать тесты всех сервисов
```

Каждый сервис остаётся самостоятельной сборкой — его можно открыть и запустить
отдельно, как если бы он жил своим репозиторием.
